# ワケワケ — タスクを分けて、次の一手へ

大きなタスクを、**実行できる大きさになるまで分解**して、
**「いま」の一番上から手をつける**ためのアプリです。

ブラウザだけで動く PWA なので、ホーム画面に追加すればアプリのように使えます。
同じリポジトリで動いている記録アプリ「ログ」とは、コードもデータも別です。

- 公開 URL: https://app.oshihitsuji.jp/wake/

## 考え方

分解する理由は「手がつけられる大きさにするため」です。
そこでこのアプリは、**葉タスク（それ以上分解されていない末端）＝いま実行できる単位**
と決めて、すべての画面をその計算の見せ方として組み立てています。

木を眺めて満足しないように、起動して最初に出るのは木ではなく「いま」の一覧です。

## 5つの画面

| 画面 | 何が出るか |
|---|---|
| **いま** | 未完了の葉タスクだけを、階層を無視して期限の近い順に並べる。上から順に手をつける |
| **分解** | 親タスクごとの木。行の ＋ で分解、行をタップで編集、▾ で折りたたみ |
| **期限** | 超過 / 今日 / 今週 / それ以降 / 期限なし に区切った一覧 |
| **カレンダー** | 月表示のマスに、その日が期限のタスクを色付きのチップで。日をタップで詳細 |
| **設定** | 完了タスクの表示、親タスクの色、バックアップと復元 |

「分解」「期限」「カレンダー」の上には**親タスクの切替バー**が出ます。
色チップをタップすると1つの親タスクだけに絞り込め、「すべて」で全部に戻ります。
（親タスクが1つのときは、切り替える意味がないので出ません）

## 決まりごと

- **期限**は日付だけを持ちます（時刻は持ちません）
- **親タスクの期限**は、手で入れていなければ**子のうち最も遅い期限**になります。
  自動で決まった期限は破線のバッジで示され、日付を入れるとそちらが優先されます
- **親タスクの完了**は、**子が全部完了すると自動**で完了になります。
  「子が全部終わっても自分の作業が残る」ものは、シートの
  「子が全部終わっても、自分で完了にする」を入れてください
- 枝タスクのチェックを押すと、**配下の葉タスクをまとめて**完了／未完了にします
- 追加は**1行に1つ**。まとめて書いて一度に子タスクにできます
- 削除は子ごと消えます。消したあとはトーストの「取り消す」で戻せます

## データについて

タスクは **端末のブラウザ内（localStorage）にのみ** 保存されます。サーバーには何も送られません。

- 端末やブラウザをまたいだ同期はされません
- ブラウザのデータ削除や機種変更で消えます
- 設定の「バックアップを保存」で JSON として書き出し、「復元」で読み戻せます

## ローカルで動かす

```bash
# リポジトリのルートで
python3 -m http.server 8000
# → http://localhost:8000/wake/index.html
```

> Service Worker は `https://` または `localhost` でのみ動きます。

## ファイル構成

```
index.html              画面の骨格
css/style.css           スタイル（ライト / ダーク自動切り替え）
js/store.js             データ層（localStorage の読み書き・木の整合・取り消し）
js/model.js             木の計算（自動期限・自動完了・葉タスクの抽出）
js/ui.js                日付まわりと共通UI部品（シート・トースト）
js/task.js              タスク1件の追加・編集・完了
js/now.js               「いま」画面
js/due.js               「期限」画面
js/tree.js              「分解」画面
js/calendar.js          「カレンダー」画面
js/app.js               画面の切り替えと設定
manifest.webmanifest    PWA 設定
sw.js                   Service Worker（スコープは /wake/）
icons/                  アプリアイコン
```

## データ構造

```js
// タスク1件（親も子も同じ形。parentId で木をつなぐ）
{
  id:        "t...",
  parentId:  null,          // null ならルート（＝親タスク）
  rootId:    "t...",        // 色と絞り込み用。ルートは自分のid
  title:     "確定申告を出す",
  due:       null,          // null＝子から自動算出 / 値あり＝手入力での上書き
  done:      false,         // 葉タスクの完了。枝は子から自動で決まる
  ownDone:   false,         // true の枝は、子が全部終わっても自分の完了が要る
  order:     0,             // 同じ親の中での並び順
  memo:      "",
  collapsed: false,
  color:     "#3f7fb5",     // ルートだけが持つ
  createdAt, updatedAt
}
```

保存データの `version` で世代を見分けます。古い世代のデータは、
タスクを消さずに不足しているものだけを足す形で移行します（`store.js` の `migrate`）。

## 既存アプリとの同居

- 記録アプリ「ログ」は `/log/`、ワケワケは `/wake/` に置いています。
  Service Worker のスコープがそれぞれの階層に閉じるので、
  片方がもう片方のリクエストを拾うことはありません
- 保存キーは `wake.v1`。「ログ」の `actionlog.v1` とは別物です
- 公開は `.github/workflows/pages.yml` が `wake` ごとコピーします

## 今後の拡張案

- **保存先の強化** — localStorage は端末側の都合で消えることがあるため、IndexedDB への移行
- **並べ替え** — いまは「上へ／下へ」と1階層の昇格・降格のみ。任意の親へのドラッグ移動
- **期限の .ics 書き出し** — 端末標準のカレンダーに登録して通知させる
- **PCでの2カラム表示** — 左に木、右に「いま」
