# シオリ — 旅の予定と持ちもの

旅の予定を **24時間のタイムラインに置いて組み立てる**ためのアプリです。
時間を空間として見せるので、**空いている時間帯が余白として見えます**。

ブラウザだけで動く PWA なので、ホーム画面に追加すればアプリのように使えます。
同じリポジトリで動いている「ログ」「ワケワケ」とは、コードもデータも別です。

- 公開 URL: https://app.oshihitsuji.jp/trip/

## 考え方

このアプリで一番大事な一動作は「予定を組み立てる」ことです。
だから起動して1枚目に出るのは、旅行の一覧でも設定でもなく、
**その日1日の時間そのもの**です。

縦軸は時間に比例させています。「空き30分」と文字で書くより、
何も置かれていない空間が見えることのほうが、組み立てには効きます。

合計金額や総移動時間は**出しません**。あれは完成した旅程を点検する指標で、
組み立てている最中には邪魔になるからです（1件ごとの費用欄は残してあります）。

## 4つの画面

| 画面 | 何が出るか |
|---|---|
| **行程** | その日の24時間。予定は所要時間ぶんの高さで置かれる。横スワイプで日を移動 |
| **持ちもの** | カテゴリ別のチェックリスト。予定と結びつけられる（「開場 で使う」） |
| **旅行** | 「これからの旅行」と「旅の記録」の一覧。タップで切り替え |
| **設定** | 旅行名と日付、持ちもののカテゴリ、バックアップ |

## 決まりごと

- **倍率は2段。** 「通常」は1時間44pxで、地名や費用まで読めます。
  「一望」は24時間を画面の高さに収めます。文字は消えて色帯だけになりますが、
  どの時間帯が空いているかが一目で分かります
- **期間と点**を区別します。滞在や移動は「期間」、開場・開演のように
  **その時刻であること自体が情報**の予定は「点」で、右の細い列に並びます
- **終了時刻は開始＋所要から自動**で決まります。手で入れる欄は作らず、
  自動で決まったことが分かるよう破線のバッジを出します
- **行き先候補**は、まだ時刻を決めていない行きたい場所の置き場です。
  「置く」を押してからタイムラインをタップすると、その時間に入ります。
  日をまたいで動かすときも、いったんここへ戻すのが確実です
- **重なりは禁止しません。** 横に割って並べ、前の予定の終わりが次の始まりを
  追い越したら赤い枠で示します。破綻を隠さず見せるのが組み立ての支援です
- **空き時間の枠**は、予定と予定のあいだが45分以上あいたときだけ出します。
  旅程の前後（就寝帯）には出しません
- 予定はドラッグで動かせます（5分刻み）。空いている場所をタップしても、
  その時刻を初期値に追加シートが開きます（こちらは15分刻み）
- 「行き先候補」の隣の「移動」ボタンから、種別「移動」で開始する予定を素早く足せます
- 削除したものはトーストの「取り消す」で戻せます。ただし**旅行の削除だけは
  2段階**です。中身（予定・持ちもの）ごと消える、最も範囲の広い操作のため、
  1回目のタップでは何も消えず「本当に削除」に変わるだけで、2回目で消えます

## データについて

旅程は **端末のブラウザ内（localStorage）にのみ** 保存されます。サーバーには何も送られません。

- 端末やブラウザをまたいだ同期はされません
- ブラウザのデータ削除や機種変更で消えます
- 設定の「すべての旅行を書き出す」で JSON として保存し、「読み込む」で戻せます

## ローカルで動かす

```bash
# リポジトリのルートで
python3 -m http.server 8000
# → http://localhost:8000/trip/
```

> Service Worker は `https://` または `localhost` でのみ動きます。

## ファイル構成

```
index.html              画面の骨格
css/style.css           スタイル（ライト / ダーク自動切り替え）
js/store.js             データ層（localStorage の読み書き・世代移行・取り消し）
js/ui.js                日付まわりと共通UI部品（アイコン・シート・トースト）
js/model.js             導出（日付の展開・重なりの列割り・空き時間・状態の判定）
js/item.js              予定1件の編集シートと、行き先候補のシート
js/plan.js              「行程」画面（タイムライン・ドラッグ・配置）
js/gear.js              「持ちもの」画面
js/trips.js             「旅行」画面
js/app.js               画面の切り替えと「設定」画面
manifest.webmanifest    PWA 設定
sw.js                   Service Worker（スコープは /trip/）
icons/                  アプリアイコン（水色）
```

## データ構造

```js
// 旅行1件。予定と持ちものを丸ごと抱える
{
  id:       "p...",
  title:    "名古屋 一泊遠征",
  start:    "2026-10-24",   // "YYYY-MM-DD"
  end:      "2026-10-25",
  items:    [ /* 予定 */ ],
  gear:     [ /* 持ちもの */ ],
  gearCats: ["貴重品", "現場グッズ", ...],   // 並び順そのもの
  createdAt, updatedAt
}

// 予定1件
{
  id:    "i...",
  kind:  "span",        // "span"＝期間 / "point"＝時刻だけ
  cat:   "live",        // move / see / eat / live / stay / etc
  title: "物販に並ぶ",
  day:   "2026-10-24",  // null なら行き先候補
  time:  "16:00",       // null なら行き先候補
  dur:   90,            // 分。point では常に 0
  cost:  8000,
  place: "日本ガイシホール 西側",
  memo:  ""
}

// 持ちもの1件
{
  id:     "g...",
  name:   "チケット",
  cat:    "貴重品",     // gearCats に無い名前なら「その他」扱い
  done:   false,
  linkId: "i..."        // 結びつけた予定のid。null なら結びつけなし
}
```

保存データの `version` で世代を見分けます。古い世代のデータは、
中身を消さずに不足しているものだけを足す形で移行します（`store.js` の `migrate`）。

## 既存アプリとの同居

- 「ログ」は `log/`（→ `/log/`）、「ワケワケ」は `wake/`（→ `/wake/`）、
  シオリは `trip/`（→ `/trip/`）。Service Worker のスコープがそれぞれの階層に
  閉じるので、互いのリクエストを拾うことはありません
- 保存キーは `trip.v1`。`actionlog.v1` / `wake.v1` とは別物です
- アイコンの地色は水色。ログ（青）とワケワケ（緑）と並べて見分けがつきます
- 公開は `.github/workflows/pages.yml` が `trip` ごとコピーします

## v1で削ったもの

- **端末間の同期** — JSON の書き出し／復元が引き継ぎ手段
- **地図・経路検索・所要時間の自動計算** — 手で入れる
- **通知** — ブラウザだけでは確実に出せない
- **写真の添付、繰り返しの旅程、費用の合計と精算**

## 今後の拡張案

- **`.ics` 書き出し** — 端末標準のカレンダーに入れて、当日の通知に使う
- **日ごとの複製** — 「前日と同じ宿」のような繰り返しを1タップで
- **保存先の強化** — localStorage は端末側の都合で消えるため、IndexedDB への移行
- **PCでの複数日表示** — 横に日を並べて、日をまたぐ組み替えを直接ドラッグで
