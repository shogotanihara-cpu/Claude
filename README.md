# ログ — 体調記録アプリ

睡眠・服薬・体調を、縦型（バーチカル）のタイムラインで記録するアプリです。
記録した内容は、受診時にそのまま見せられる1枚のレポートにまとめられます。
ブラウザだけで動く PWA なので、ホーム画面に追加すればスマホアプリのように使えます。

> 記録の保存と表示のみを行います。診断や治療の判断は行いません。

## できること

- **ワンタップ記録** — 睡眠の開始／終了、服薬、体調を、タイムライン上部のボタンから1回のタップで記録
- **3種類の記録**
  - **期間** … 睡眠など、長さがあるもの（日をまたぐ記録にも対応）
  - **点** … 服薬など、その瞬間の出来事
  - **体調** … そのときの状態を 1〜5 で記録
- **バーチカルタイムライン** — 24時間の縦軸に、記録をブロックで表示
- **継続中の記録** — 終了時刻を空にして開始し、あとから「終了」で締める
- **受診用レポート** — 期間内の睡眠（帯グラフ）・服薬（回数と記録のない日）・体調の推移・メモを
  1枚にまとめ、印刷や PDF 保存でそのまま渡せる
- **サマリー** — 週 / 月 / 3ヶ月を切り替え。日を横に・時刻を縦に並べたミニタイムラインで
  「いつ」記録したかを一望できる。体調の推移、カテゴリ別の集計もあわせて表示
- **リマインダー** — 決めた時刻までに記録がなければ知らせる（下記参照）
- **検索・絞り込み** — メモとカテゴリ名での検索、カテゴリでの絞り込み
- **書き出し** — JSON バックアップ（復元用）と CSV（表計算ソフト用）
- **オフライン動作** — Service Worker でアプリ本体をキャッシュ（Webフォントは使わない）

## リマインダーについて

ブラウザだけで動くアプリには、**閉じている間に決まった時刻の通知を出す確実な手段がありません**。
それには Web Push とサーバーが必要で、iOS ではとくに制約が大きくなります。
そこで3段構えにしています。

| 方法 | 動く条件 | 確実さ |
|---|---|---|
| **アプリ内の声かけ** | アプリを開いたとき | 必ず動く |
| **ブラウザ通知** | アプリを開いている間だけ | 環境しだい |
| **カレンダーに登録（.ics）** | 端末標準のカレンダーが鳴らす | 確実 |

iPhone で確実に知らせてほしい場合は、設定の「カレンダーに登録」をお使いください。
書き出した `.ics` を開くと、毎日くり返す予定として登録されます。

## 公開先

`main` ブランチに変更が入ると GitHub Actions（`.github/workflows/pages.yml`）が
自動で GitHub Pages にデプロイします。

- 公開 URL: https://app.oshihitsuji.jp/log/
- アプリ本体は `/log` 以下に配置しており、ドメイン直下（`/`）には何も置いていません。

同じドメインで運用しているブログとは別のサブドメインに置いています。
ブログの apex（`oshihitsuji.jp`）のレコードには一切触れていません。
アプリからブログへのリンクはなく、`noindex` と `robots.txt` で検索結果にも出しません。

### 初回だけ必要な設定

1. **DNS** — `app` の CNAME レコードを `shogotanihara-cpu.github.io.` に向ける
2. **GitHub** — Settings → Pages → Build and deployment → Source を **「GitHub Actions」** に変更
3. DNS の確認が通ったら、同じ画面で **Enforce HTTPS** を有効にする

カスタムドメインはリポジトリ直下の `CNAME` ファイルで指定しており、
ワークフローが公開ファイルに含めます。

（`configure-pages` の `enablement` による Pages の自動有効化は、GITHUB_TOKEN に
Pages サイトの作成権限がないため使えません。手順 2 は手動で行う必要があります。）

## ローカルで動かす

静的ファイルだけで動くので、Web サーバーに置くか、ローカルで配信します。

```bash
python3 -m http.server 8000
# → http://localhost:8000/index.html
```

スマホで使うときは、上記の URL をブラウザで開き、共有メニューから
「ホーム画面に追加」を選ぶとアプリとして起動できます。

> Service Worker は `https://` または `localhost` でのみ動きます。
> `file://` で直接開いた場合、アプリ自体は動きますがオフラインキャッシュは無効です。

## データについて

記録は **端末のブラウザ内（localStorage）にのみ** 保存されます。サーバーには何も送られません。

- 端末やブラウザをまたいだ同期はされません
- ブラウザのデータ削除や機種変更で消えます
- 設定画面の「バックアップを保存」で JSON として書き出し、「復元」で読み戻せます

## ファイル構成

```
index.html              画面の骨格
css/style.css           スタイル（ライト / ダーク自動切り替え）
js/store.js             データ層（localStorage の読み書き）
js/ui.js                日付ユーティリティと共通UI部品
js/timeline.js          バーチカルタイムラインの描画
js/summary.js           集計とグラフ
js/report.js            受診用レポートの生成
js/export.js            CSV とカレンダー(.ics)の書き出し
js/notify.js            リマインダー
js/app.js               画面制御
manifest.webmanifest    PWA 設定
sw.js                   Service Worker
icons/                  アプリアイコン
```

## データ構造

```js
// ログ1件
{
  id:    "l...",                    // 自動採番
  catId: "c_sleep",                 // カテゴリID
  type:  "span" | "point" | "scale",
  start: 1757203800000,             // 開始（epoch ミリ秒）
  end:   1757232600000,             // 終了。null なら継続中。span 以外は常に null
  scale: null,                      // type が "scale" のとき 1〜5
  memo:  "頭が重い"
}

// カテゴリ
{
  id: "c_sleep", name: "睡眠", color: "#5b63b7",
  kind: "span",     // 既定の記録方法
  quick: true       // タイムライン上部のワンタップ記録に出すか
}

// リマインダー
{ id: "r...", time: "22:00", catId: "c_med" }  // catId が null なら記録全体が対象
```

保存データの `version` で世代を見分けます。古い世代のデータは、記録を消さずに
不足しているものだけを足す形で移行します（`store.js` の `migrate`）。

## このリポジトリのもう1つのアプリ

`wake/` に、タスク管理アプリ **「ワケワケ」**（https://app.oshihitsuji.jp/wake/ ）が入っています。
大きなタスクを分解して、次に手をつけるものを1枚目に出すアプリです。
コードもデータ（localStorage のキー）も、このアプリとは分かれています。
くわしくは [`wake/README.md`](wake/README.md) を見てください。
