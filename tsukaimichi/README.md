# ツカイミチ — 使い道を、自分の軸で

ザイムに記録した支出を取り込んで、**推し活・生活・娯楽**という自分の軸で見直すためのアプリです。
ザイムが元帳で、こちらはそれを別の切り口で眺めるレンズにあたります。

ブラウザだけで動く PWA なので、ホーム画面に追加すればアプリのように使えます。
同じリポジトリのほかのアプリとは、コードもデータも別です。

- 公開 URL: https://app.oshihitsuji.jp/tsukaimichi/

## 考え方

一番大事な一動作は「今月、どの軸にいくら使ったかを見る」ことです。
だから起動して最初に出るのは、明細でも分類の編集でもなく、3つの合計です。

明細は何千件も入りますが、1件ずつ確かめさせることはしません。
自動で振り分け、**決めきれなかったものだけ**を「仕分け」に出します。

## 5つの画面

| 画面 | 何が出るか |
|---|---|
| **月** | その月の合計、3分類の金額と割合、小分類の内訳、前月比、年の合計 |
| **仕分け** | 自動では決めきれなかった明細。日付ごとにまとまり、3つのボタンで入れ先を決める |
| **明細** | 月ごとの明細を日付順に。大分類・小分類で絞り込み、タップで編集。＋ で手入力 |
| **イベント** | 遠征や旅行などの束。期間内の明細が候補に並び、入れると合計が出る |
| **設定** | CSVの取り込み、分類の編集、ザイムのカテゴリとの対応、バックアップと復元 |

## 決まりごと

### 取り込み

- ザイムの「ファイル入出力」で書き出したCSV（Shift_JIS）をそのまま選びます
- 取り込むのは**支出（payment）だけ**。収入・振替・残高調整は対象外です
- 値引きや返金（支出がマイナスの行）は、マイナスのまま入れて合計から差し引きます
- ザイムで「集計に含めない」にしてある支出は、こちらでも集計の外に置きます
- **同じ期間を重ねて取り込んでも二重になりません。** ザイムのCSVには明細のIDがなく、
  「同じ日・同じ区間の電車に2回」のように同じ内容の行が正しく複数あるので、
  有無ではなく件数で比べて、足りない分だけを入れます
- このアプリで日付やメモを直した明細、削除した明細は、再取り込みで戻りません
- ザイム側で金額や日付を後から直すと、別の明細として入ります（IDがないため避けられません）

### 自動の振り分け

上にあるものほど優先します。

1. **手で決めた履歴** — 同じお店 × 同じザイム内訳の明細を、これまでどこに入れたかの多数決。
   2回以上あって、3分の2以上が同じ行き先のときだけ採用します
2. **ザイムのカテゴリとの対応表** — 初期値は ホロライブ → 推し活、旅行 → 推し活（仮置き）、
   エンタメ → 娯楽、それ以外 → 生活。設定で変えられます
3. どちらにも当たらなければ**未分類**として仕分けに出ます

- 小分類は、はじめて取り込んだときにザイムの内訳の名前で自動的に作られます。
  あとから改名・別の大分類への付け替え・削除ができます
- 手で分類を決めた明細は、もう自動では動きません。
  自動のままの明細には破線の「自動」が付きます
- 「旅行」は推し活に仮置きしたうえで、毎回仕分けに出ます（推し活でないこともあるため）

### イベント

- イベントは**分類とは別の軸**です。「生活／外食」の明細が、同時に「○○遠征」にも入れます
- イベントに入れても、分類と月の集計は変わりません
- 期間の外の明細（事前に買ったチケットなど）は、明細のシートでイベントを選んで入れます

## データ

- 保存先は端末のブラウザの中（localStorage の `tsukaimichi.v1`）だけです。サーバーには何も送りません
- 数千件を入れるため、保存するときだけ項目名を縮めています（`js/store.js` の `pack`）。
  1年半・約4,400件で約68万文字。ブラウザの上限の目安は250万文字ほどです
- 設定からJSONで書き出し／復元ができます

## v1 で入れていないもの

予算（上限）、検索、グラフ、1つの明細を複数の分類に割ること、ザイムへの書き戻し。
